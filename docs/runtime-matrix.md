# Runtime matrix

What each runtime gets from this repository, and what it does not. One canonical source; the Codex and Gemini adapters are generated by `scripts/build-runtimes.py` and must never be edited by hand (`--check` fails CI if they drift).

| Feature | Claude Code | OpenAI Codex CLI | Gemini CLI |
|---|---|---|---|
| Skills (`skills/<name>/SKILL.md`, Agent Skills format) | Native: marketplace plugin, `/plugin:skill` | Native: `.agents/skills/<plugin>-<skill>/` in the repo, or `~/.agents/skills/` for use anywhere; invoke with `$plugin-skill` or by description | Native: extension `skills/<plugin>-<skill>/`; also `/plugin:skill` via generated `commands/*.toml` |
| Shared guardrails (plugin `CLAUDE.md` sections) | Plugin `CLAUDE.md` template (not project context; the cold-start interview copies it to the profile) | `AGENTS.md` at the repo root (generated); copy to `~/.codex/AGENTS.md` for global use | `GEMINI.md` context file of the extension (generated) |
| Practice profile | `${LEGAL_CONSULTANT_HOME:-~/.legal-consultant}/<plugin>/CLAUDE.md` | same path | same path |
| Jurisdiction tree (`references/jurisdictions/`) | Repo root and a copy inside each plugin (`scripts/sync-jurisdictions.py`) | `legal-consultant-jurisdictions` skill folder | `legal-consultant-jurisdictions` skill folder |
| Primary-source fetch (`scripts/fetch-law.py`) | Bash tool | Shell tool | Shell tool |
| Subagents (`agents/*.md`: renewal-watcher, deal-debrief, playbook-monitor, dataroom-watcher, leave-tracker) | Native subagents, on-demand or scheduled by the user | **Not ported.** Run the equivalent skill on demand (`renewal-tracker`, `leave-tracker`, `review-proposals`); no background agent | **Not ported.** Same on-demand workaround |
| Hooks (`hooks/hooks.json`) | Native (all three plugins ship an empty stub upstream) | Not available; nothing to port today | Not available; nothing to port today |
| Scheduled runs | User-side scheduling (cron, `/schedule`) | User-side scheduling only | User-side scheduling only |
| MCP connectors (`.mcp.json`) | Plugin-bundled servers (Ironclad, DocuSign, Slack, Drive, Box, iManage, …) | Configure per server in `~/.codex/config.toml` `[mcp_servers.<name>]`; not generated | Configure in `gemini-extension.json` `mcpServers` or `~/.gemini/settings.json`; not generated (the manifest ships without servers) |
| Legal research connectors (CourtListener, Westlaw) | Only relevant when `usa` is in the footprint | same | same |
| Bilingual output, disclaimer, provenance tags | Skill text + guardrails | Skill text + `AGENTS.md` | Skill text + `GEMINI.md` |
| Validation | `claude plugin validate`, `scripts/*.py` | `scripts/build-runtimes.py --check` | `scripts/build-runtimes.py --check` |

## Known limitations

- The generated skill copies carry a runtime preamble that re-maps two things the canonical text assumes: the Claude Code config path and the location of the jurisdiction tree. Everything else in the skill body is identical across runtimes.
- Gemini custom commands wrap the skill in a one-line prompt; argument parsing (`--flag` forms in `argument-hint`) is passed through as `{{args}}` and interpreted by the skill text.
- Codex's initial skills listing is capped (about 8,000 characters); with 40 skills plus the jurisdiction skill the descriptions are truncated in the listing but the skills remain invocable by name.
- Neither adapter ships MCP server definitions, because the upstream `.mcp.json` entries are hosted-connector URLs with per-user authentication; configure the ones you use (Slack, Google Drive, DocuSign) in the runtime's own config.
