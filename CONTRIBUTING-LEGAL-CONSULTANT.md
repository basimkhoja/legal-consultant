# Contributing to Legal Consultant (fork notes)

Upstream's `CONTRIBUTING.md` still applies: doctrine goes in the skill, `CLAUDE.md` guardrails are the net, provenance tags go on the load-bearing digit, decline pathways are scaffolds. These notes cover what the fork adds.

## Layout the fork adds

```
references/jurisdictions/            canonical doctrine layer (all jurisdictions)
  REGISTRY.md                        every code and its populated status
  JURISDICTION-STEP.md               canonical "Step 0" wording every skill copies
  _TEMPLATE-instrument.md            template for a new instrument file
  <code>/MANIFEST.md                 name, legal family, language, portal, populated yes/no, calendar, disclaimer
  <code>/INDEX.md                    generated by scripts/build-jurisdiction-index.py
  <code>/SOURCES.md                  source hierarchy, every URL read, post-cutoff check
  <code>/playbook-defaults.md        defaults the cold-start interview offers
  <code>/<instrument>.md             one file per instrument, rules table with provenance tags
<plugin>/references/jurisdictions/   copy, written only by scripts/sync-jurisdictions.py
.agents/, AGENTS.md, gemini-extension/   generated adapters, written only by scripts/build-runtimes.py
scripts/fetch-law.py                 official-portal fetcher (adapter per portal; `boe` today)
docs/                                inventory, coverage, amendment watch, open questions, phase reports
tests/scenarios/, tests/results/     behavioural scenarios and run logs
```

## Rules

1. **Every rule row cites the primary text or says it does not.** The Tag column is `[settled — last confirmed YYYY-MM-DD]` only when the text was read on that date; otherwise `[model knowledge — verify]`. `scripts/build-jurisdiction-index.py <code>` refuses to build an index with an untagged row.
2. **Skills branch on the profile, never on a country.** Skill prose says "the applicable jurisdiction file". Country names live inside `references/jurisdictions/<code>/` and the profile.
3. **Unpopulated jurisdiction is a hard stop.** A skill that meets `populated: no` stops for that code. Never add a fallback.
4. **Additive edits.** Add steps and branches; keep the upstream US path under "When the applicable code is `usa`". Never remove a shared guardrail.
5. **Config path.** `${LEGAL_CONSULTANT_HOME:-~/.legal-consultant}/<plugin>/CLAUDE.md`. Do not reintroduce the upstream path.

## Before every commit

```bash
python3 scripts/build-jurisdiction-index.py ksa --check      # tags and index freshness
python3 scripts/sync-jurisdictions.py --check                # plugin copies current
python3 scripts/build-runtimes.py --check                    # adapters current
claude plugin validate .claude-plugin/marketplace.json
for d in commercial-legal corporate-legal employment-legal; do claude plugin validate "$d"; done
python3 scripts/lint-tool-scope.py
python3 -c "import json,glob; [json.load(open(f)) for f in glob.glob('**/*.json', recursive=True)]"
```

If you edited anything under `references/jurisdictions/` run `scripts/build-jurisdiction-index.py <code>` and `scripts/sync-jurisdictions.py` first; if you edited a skill or a plugin `CLAUDE.md`, run `scripts/build-runtimes.py`.

## Fetching a primary source

```bash
python3 scripts/fetch-law.py --portal boe --search "نظام العمل"        # find the GUID; check the status column, repealed laws share titles
python3 scripts/fetch-law.py --portal boe --id <guid> --lang ar --out /tmp/law.md
python3 scripts/fetch-law.py --portal boe --id <guid> --attachments      # official translation PDFs
```

The output marks amended articles `[معدلة]`: the body is the original text and the last "تعديلات المادة" block is the wording in force. The fetcher warns when the portal status is `لاغي` (repealed).
